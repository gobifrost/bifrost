# B2 — Recorded semantic checks without replaying uncertain model calls

Approved after B1 and shared quality-usage foundation acceptance (primary independently verified 60 accounting/legacy tests). This does not implement automatic applicability or finish the broader workbench. Native worker executes; primary reviews. Global reporting and existing synthetic-caller integration follow separate packets; this slice must write shared accounting for every new recorded judge call.

## Public behavior

Add `judge_mode: exact|semantic` (default exact) to the recorded admission DTO and CLI `--judge`. Freeze mode and selected job type in the domain input and include mode in dedupe. Preserve exact behavior. Semantic admission requires `user.is_superuser`, matching existing `freeze_semantic_judges` policy; do not broaden privileges in this slice. Use accepted case assertions' existing server-frozen judge_snapshot, never a client-supplied replacement profile.

Applicability stays caller-declared. Unknown/not-applicable pairs never call a judge. Deterministic assertions still use A1. Only applicable pending llm_judge assertions are candidates for semantic execution.

Add optional `params.recorded_evidence_requirements` to llm_judge assertion validation. If present, require a nonempty unique list of recognized A1 completeness dimensions. Existing assertions without it remain valid and simulation semantics remain unchanged, but recorded semantic evaluation returns insufficient_evidence without a model call. Do not infer evidence requirements from rubric prose or use a permissive default that ignores missing cost/tool evidence.

Before calling a model, every declared dimension must be complete and its evidence value present. Missing/redacted/unsupported evidence yields insufficient_evidence and names the missing dimensions. A2 token/cost coverage remains incomplete: budget rubrics requesting it cannot pass via a model. Do not invent simulator state or successful tool side effects from requests.

## Exact input projection

Only declared evidence goes to the judge. `terminal_status` and `output` copy their matching values. `tool_calls` supplies names/counts in canonical non-causal order, without arguments or journal sequence; `tool_order` supplies the proven ordered names; `tool_arguments` supplies names/arguments without implying causal order. `delegation` supplies the recorded tree; `real_tool_executions` the count. Dotted `usage.*` copies only requested fields, never all usage. Required unsupported dimensions remain insufficient. Persist selector/prompt version and hash so the exact request can be reconstructed from the domain's frozen evidence and case snapshot; do not duplicate full evidence for every pair/assertion.

The system instruction treats evidence as data, not instructions, and requires a structured verdict: `sufficient_evidence: bool`, `score: number|null`, `rationale: string`. If sufficient is false, return nonpassing insufficient_evidence. If true, require a finite numeric score 0..1 (not bool/string) and compare against the frozen threshold. Bound rationale and input size; reject oversize without truncating evidence. Mark model judgement nonauthoritative/nondeterministic. Profile drift, provider errors, malformed JSON or invalid scores are execution errors, not assertion failures. Store generic sanitized error codes/messages; no raw provider exceptions that may contain credentials.

Implement a dedicated shared recorded-judge helper using existing LLM config/client abstractions. Resolve and compare frozen profile settings inside a short read context, close it before the model request, and never hold a write transaction/row lock across the request. Do not call the old synthetic execute_semantic_judge helper, which collapses errors into failed assertions; leave that existing contract unchanged.

## Durability and cost

Register `agent.evaluation_recorded_semantic` in the SAME PlatformJob registry, with max_attempts=1 and retry_on_runner_loss=False. Use existing domain/result storage and handler entry point; no new worker, job table, status route, scheduler callback or transport. Exact jobs retain their retry policy. Handler verifies frozen mode/job type match the bound PlatformJob.

Before each model request, use the approved shared quality-usage foundation to begin an accounting attempt and persist its ID plus that assertion's stable index/hash and `judge_execution_state=started` in a partial pair result under the current job fence, then commit atomically. The shared attempt is the call identity; the pair stores only the reference and verdict projection, not a second independent attempt lifecycle. Its assertion outcome is pending_judge, passed=false; partial pair complete/gate_passed are false. Only a newly created attempt permits the first model request. Completed assertion outcomes are reused if handler is called again. A started marker without a persisted verdict must NEVER trigger another call: classify it as error with `judge_attempt_ambiguous`. A fresh user-requested evaluation is a new explicit operation, not a hidden retry.

After the model response, persist factual usage through the shared strict accounting writer against the committed matching attempt, even if cancellation or lease loss prevents the verdict write. This observation authorizes no new call or domain mutation. Then fence again before recording the verdict. If lease/cancellation wins, no stale result write. The marker preserves verdict uncertainty even when actual spend is known. Results reading a terminal failed/cancelled job must project unfinished markers as ambiguous errors, never imply they are still processing or cost-free. Reuse generic job lifecycle; no reconciliation loop is needed. Preserve already completed outcomes. Aggregate verdicts only from persisted outcomes and costs only from shared accounting, not duplicated JSON subtotals.

Capture observed judge input/output/cache token fields and provider cost when available, including responses whose JSON later fails parsing. Integrate with `shared.quality_usage` and the accepted accounting foundation, with operation type `recorded_evaluation` and purpose `recorded_semantic_judge`. Use evaluation ID, stable case/run/assertion identity, frozen profile identity and request fingerprint. The committed accounting-attempt ID is returned in each assertion outcome for provenance. Never include keys or arbitrary profile options in accounting records. Keep source-run usage separate: evaluating historical evidence must not rebook its cost. Missing provider cost/ambiguous calls mean cost coverage unknown, not zero; distinguish observed provider cost from estimates. Shared per-operation/global aggregation is a separate next packet; do not create a competing JSON cost total or report endpoint here. Do not claim end-to-end exactly-once provider billing; job policy and markers prevent our automatic replay after worker loss.
