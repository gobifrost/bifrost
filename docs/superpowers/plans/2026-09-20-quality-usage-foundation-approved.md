## Accounting model

Reuse `AIUsage` as the only monetary/token ledger. Add nullable `quality_operation_type` (varchar), `quality_operation_id` (UUID), `quality_operation_item_id` (bounded varchar), `usage_purpose` (varchar), `profile_id` (UUID identity, no mutable profile FK), `profile_name` (bounded varchar), `profile_fingerprint` (bounded varchar), and `usage_attempt_id` (nullable unique FK to the new attempt record). Keep all existing columns and old call behavior. Extend the context check to allow a complete operation type/id pair; reject half-pairs independently. New quality rows must not attach to production AgentRun/execution/conversation contexts. No migration of old rows or invented historical attribution.

Add shared `AIUsageAttempt` in the same ORM module and export it. It records accounting intent, not work scheduling: no worker, retries, job status route, progress event, or poller. Fields: UUID id, unique bounded idempotency key, immutable operation type/id/item, purpose, nullable organization/user IDs consistent with existing globally scoped operations, optional PlatformJob FK SET NULL, profile identity fields above, provider/model, bounded request fingerprint, started_at, observed_at, and state (`started`, `observed`, `unobserved`). The relationship goes only from AIUsage.usage_attempt_id to the attempt; no circular foreign keys. Attempt has no raw prompt, evidence, credentials, arbitrary profile config, or provider exception text. A small allowlisted reason code may describe unobserved usage. Deleting an attempt with usage must be restricted; deleting a domain/job must not erase new accounting provenance.

Operation types: `recorded_evaluation`, `synthetic_evaluation`, `agent_review`, `quality_designer`. Purposes: `recorded_semantic_judge`, `synthetic_semantic_judge`, `agent_review`, `test_designer`. Existing runtime purposes will be classified on read in a later packet, not retroactively duplicated. Profile/provider/model identities are captured before calling; unknown profile name/id stays null, never resolved from a later mutable profile.

## Internal service contract

Implement in `api/shared/quality_usage.py` (business logic belongs in shared). If typed models are needed, define them in `api/shared/models.py`; do not place Pydantic DTOs elsewhere. Do not add a public mutation endpoint.

`begin_quality_usage_attempt`: caller owns short transaction and must hold its existing domain/job fence. Insert durable immutable marker by idempotency key; return marker and whether newly created. Duplicate matching input returns existing marker without another authorization to call; same key with changed identity/fingerprint rejects. Use PostgreSQL conflict handling safe under concurrent duplicates. Caller must commit before model request. Helper itself never invokes provider or commits caller transaction.

`record_quality_usage_observation`: record factual observed usage against a previously committed matching marker using a separate short transaction. Takes marker identity plus request fingerprint; validates immutable provenance; acquires attempt lock. It may run after cancellation or lease loss: this records already-incurred cost only, without changing domain/job verdict or authorizing another call. Require finite nonnegative integer input/output/cache counts (reject bool), finite nonnegative Decimal provider cost when supplied. Do not invent missing token counts as zero. Duplicate identical observation returns the original row; conflicting observation rejects rather than overwriting or adding cost. Atomically insert AIUsage and mark attempt observed. Never attach to source AgentRun. No second call to legacy best-effort recorder.

Price locally using existing provider canonicalization and model-pricing rows; no provider/catalog/display-name network requests, Redis calls, or model invocation in the critical transaction. Preserve exact model identifier for new calls. Provider-reported cost wins. Otherwise reuse the existing cost calculator only when the required pricing components are available; missing input/output or cache pricing must not yield an apparently complete partial estimate. Unknown cost stays null. Existing calculator/legacy callers remain unchanged. `provider_cost` distinguishes observed provider amount from estimated effective `cost`.

`mark_quality_usage_unobserved`: preserve marker as coverage gap on no usage/ambiguous response, with allowlisted reason; never insert zero-valued AIUsage. It cannot downgrade observed state. A later actual observation may settle an unobserved marker; do not reject real observed spend merely because the job already failed.

Return enough identity for later per-operation/global aggregation. No aggregate caches introduced. No claim that pre-call marker proves actual provider dispatch: a process can die before dispatch. `started` therefore means possibly incurred usage, not a zero-cost or confirmed charge. Absence of markers on legacy paths means coverage unknown, not complete.

New quality AIUsage timestamps use the original attempt's started_at so late accounting settlement stays in the original call's reporting window; observed_at records settlement time. Existing runtime timestamps are unchanged. Database constraints require a purpose for quality rows and operation context for purpose/attempt metadata; unobserved attempts require a reason. Profile/job columns are not categorically forbidden on legacy runtime rows, since future runtime attribution may legitimately populate them. Repeated provider costs normalize to the existing ledger decimal precision before comparison, and row-lock reads refresh cached ORM state before deciding whether an observation can change state.
