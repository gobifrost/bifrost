## Cross-Cutting Evidence Notes

- Browser tests that route/intercept their own APIs are useful UI contract evidence, but they do not prove live third-party provider behavior. This applies most clearly to GitHub settings, AI model settings, artifact retention cleanup, and the design-foundations branding color check.
- `client/e2e/memory.admin.spec.ts` is now valid route-specific evidence for `/settings/ai-memory`, `/settings/ai-instructions`, `/user-settings/preferences`, organization instructions, and MCP required-instructions resolution. The older concern that it only visited `/settings/ai` is obsolete.
- `client/e2e/preferred-sso.admin.spec.ts` proves login redirect behavior after API seeding. It supplements `sso-settings-acceptance.admin.spec.ts`; it does not replace settings-form evidence.
- `client/e2e/mcp-settings-acceptance.admin.spec.ts` covers platform MCP server access configuration. It is distinct from external MCP server/connection management under `/mcp-servers` and from personal connections under `/user-settings/connections`.
- `client/e2e/github-settings-acceptance.admin.spec.ts` intentionally intercepts all GitHub backend calls. It should be counted for UI persistence/reload/disconnect behavior, not for real GitHub credentials or repository creation.
- Route-string-only searches are insufficient for this inventory. Specs such as `profile-acceptance.user.spec.ts` may prove a settings default or tab through semantic UI actions and ledger IDs even when the filename does not include the tab name.

## Clear Remaining Gaps

- Platform AI: `/settings/ai-chat` and `/settings/ai-usage` now have targeted browser happy paths. AI model destructive delete, pricing failure retries, provider/model matrix variants, and embedding reindex retry remain lower-layer or pending.
- Platform connections/security: MCP settings primary lifecycle is covered; GitHub is intercepted-only; SSO covers Google but not Microsoft/OIDC-specific provider forms or provider test buttons.
- Platform branding/maintenance: Branding color and terminology are covered, but product name and logo settings are not. Maintenance retention is covered with intercepted APIs; docs indexing, dependency scan, reimport, export/import-all lack primary browser evidence.
- Account settings: Basic Info has browser evidence for display-name save/reload, but not avatar. Security has passkey browser evidence; `client/e2e/account-onboarding-acceptance.admin.spec.ts` contains TOTP/recovery-code and password-change journeys, but parent is still repairing account test setup sessions, so those remain pending here. Developer has component evidence only. Connections and Preferences have primary browser evidence, with partial-failure/responsive cases remaining below e2e.
