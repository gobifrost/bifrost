On Kubernetes, the API starts worker Jobs as work arrives and drains them when idle, keeping one warm for instant runs and up to six by default. After an upgrade, workers on the old build are replaced once a new one is ready, and their runs finish first. Set the range with `BIFROST_POOL_MIN_WORKERS` and `BIFROST_POOL_MAX_WORKERS`.
